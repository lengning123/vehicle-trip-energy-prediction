# 整程能耗预测：文献核验与下一阶段数据路线

更新：2026-09-30。研究对象是**出发前、给定计划路线、预测完整旅程能量**。本报告是阶段性核验：已逐项覆盖原综述的13项方法条目，补充相关工作和资源；部分出版商全文待用户下载，详见[逐篇证据表](论文证据表.md)及[待下载清单](待下载论文.md)。没有将摘要阅读写成全文阅读，没有执行作者代码、加载权重或启动新训练。

## 管理者摘要

文献支持把主线转向数据基础，但无需一开始从零建大车队。建议用公开纯电实测数据补机制、借用大车队预训练知识补覆盖，再少量采集完整旅程与出发时快照。别人较低的误差常依赖已知车型、实际工况或不同能量标签，不能直接照搬。IFS-Former和EnergyVille最值得先验收；逐秒速度预测与架构搜索暂缓。部分关键全文尚待补齐，资源可用性不等于本项目收益已证实。

## 1. 我们比读综述前多知道了什么

**第一，trip-level只表示输出的尺度，不保证输入在出发前可得。**输入真实整程速度统计、实际行程时间或瞬时扭矩，能得到很好的整程能耗估计，却没有解决未来驾驶的不确定性。Valladolid的路线内累计能量回归、Zhu的实测工况特征，都应作为条件估计或机制参考，而不是我们的直接性能目标。

**第二，低误差往往来自问题条件更完整或更窄。**Sequence-aware使用地图服务提供的分段时间/速度，并有车型和初始电池信息；GECR在一辆已知Tesla上做专门标定；公交研究有稳定路线、车辆参数及运营条件。这些是数据与应用设计，不是某个网络自动找到了缺失信息。

**第三，我们不必自己收集与论文同等规模的数据。**IFS-Former发布了权重分卷和测试样本，预训练时专门处理缺失字段；UPECT也提供预训练权重入口。可以借用已经学到的车队知识，再用独立纯电数据检查是否适配。这里新增的是外部经验，不是再次把eVED的历史窗口加长；E2失败没有否定这条路线。

**第四，公开数据已经可以补部分机制缺口，但没有补齐真实部署闭环。**EnergyVille包含温度、驾驶/停车/充电及附件能量，GECR提供实验室与实路成对数据，TUM UDS提供更长的车辆使用记录。它们分别有用，但不能把不同车、不同时间的字段拼成一条“全信息行程”，也不能补出当年出发时的导航预测快照。

**第五，当前模型并非完全没有改进空间。**本轮读取新产物发现E3、E4已完成：M3分解是E3唯一过门槛候选；E4相对损失把开发MAPE从25.47%降至24.11%，但偏差更负，仍是单种子。这支持监督与目标对齐有局部价值，不支持继续依赖优化达到10%。旧研究文件中“E3未完成”已同步修订。

## 2. 别人如何处理我们遇到的问题

| 我们的问题 | 文献实际处理 | 对我们的用途与限制 |
|---|---|---|
| 未来速度未知、规则耗时偏低 | Sequence-aware借助地图API分段预估；Meta-Pec检索相似路线/时段历史，预测行为统计；Jiang/Choi提出工况生成（后两篇全文待补） | 接入真实出发快照，或预测少量工况统计的分布。没有交通源时不能仅凭算法名称声称补齐了信息 |
| 纯电只有3辆、车辆身份与参数弱 | IFS/UPECT在大车队预训练，再对新车少样本适配；GECR对已知车辆分步标定 | 外部知识迁移与小样本校准可减少采集量。标签、单位、动力类型必须一致；PHEV净电不能直接当BEV总电 |
| 热状态、附件负载缺失 | Dabčević把牵引与HVAC分开，后者按平均功率乘时长；EnergyVille直接记录相关信号；Kim等附件论文待全文 | 用有实测附件的公开数据先辨认初始温度、停车/充电历史、时长是否足以解释差异，再决定本地新增字段 |
| 稀疏采样与标签不可靠 | IFS用实际时间间隔积分并按质量/行程条件筛选；GECR采用高频实测和独立仪器；低频CTSD研究提供另一候选 | 低频插值不能恢复未观测峰值；单独评估采样敏感性。不能照搬按能耗删样本规则后与原任务比较 |
| 裁剪片段冒充完整旅程 | 多数论文重新按停车/时间间隔切分，但不能因此保证点火到终点全部保留 | 现有eVED首尾缺失没有被文献“修复”。公开完整会话需核验边界；最终需少量前瞻完整旅程验证 |
| 油电混合，目标不统一 | 大量工作直接选择BEV；Meta-Pec按动力类型采用不同能量口径；Zhu只算电机侧 | 首先选定业务能量口径。纯电建立新版本；PHEV保留独立油、电目标。不能把不同论文的energy一律当电池净kWh |
| 点预测仍有长尾 | Zhu输出分位数区间，Choi报告bootstrap区间/可达概率（待全文） | 改为同时报告期望能耗和低估风险；按独立车辆/时间检验覆盖率。标称95%并不自动达到95%实测覆盖 |

## 3. 最值得使用的资源

### 3.1 IFS-Former：优先验收的外部知识来源

[论文](https://doi.org/10.3390/technologies13110493)；[作者仓库](https://github.com/W1polytechnical/IFS-Former)。全文第5–10页给出样本和特征处理，第11–17页给出跨车、少样本及缺失特征实验。

837辆车约49.3万条行程用于预训练，13辆保留车辆用于下游；输入含计划距离的代理、既往能耗率、历史驾驶/充电、起始状态、车型、天气。通过可训练的缺失嵌入和训练期字段遮蔽适应不同车辆字段。仓库确有约31.6MB的两个RAR权重分卷及6个测试CSV，但本轮只核验文件清单和读取源代码，尚未解压、运行或验收完整性；不是49万条预训练数据全部公开。

它更适合我们“车型与字段覆盖少”的问题，优先级高于从头预训练。需要注意：论文去掉<1km、<10min、<0.1kWh等样本，我们大量短片段与此不同；距离用实测值加±5%扰动模拟导航误差，不能当真实导航部署验证；预训练没有整程时间/均速，下游两车才加入这两个变量，需隔离实际值与可预测值。其缺失实验仍保留trip information，其中包括历史能耗率，不能概括成“什么输入都不需要”。R²高也不等于MAPE<10%。公开仓库未发现许可证，正式复用需澄清授权范围。

### 3.2 EnergyVille：优先验收的热状态与能量机制数据

[数据论文](https://doi.org/10.1038/s41597-025-06148-5)；[数据集](https://doi.org/10.48804/8KPDTW)；[处理代码](https://github.com/mayasko/BEV-data)。论文全文Data Records、Technical Validation、Data availability已读。

两辆Tesla Model Y、约1秒分辨率，分为1396份驾驶、780份停车、109份慢充、25份快充记录；包括电池/环境温度、电池与附件能量相关信号，文中使用GPS重建路线。数据许可CC BY 4.0。论文用外部充电设备核验若干充电会话，并比较里程表与地图距离；这不是对每一条驾驶能量的独立真值认证。

它能帮助回答：停车和充电后的热状态为什么让相同距离能耗不同；电池支出中多少来自附件；哪些出发时字段真正值得新增。不能替代多车型测试，不能假定每个公开文件都完整保留GPS和连续会话，不能据此重建当时导航预测。本轮尚未批量下载并审核数据文件，故状态为“高优先级候选”，不是“已验收主数据”。

### 3.3 GECR：用高质量小数据分离车辆与驾驶条件

[论文](https://doi.org/10.1016/j.patter.2024.100950)；[数据与代码](https://github.com/MOTIVES-LAB/generalized-energy-consumption-evaluation-for-ev)；[归档数据](https://doi.org/10.6084/m9.figshare.23904102)。一辆Model 3，34组实验室工况、106条实路。标定车辆对风阻、制动、低速等驾驶强度的响应，再用少量实路做偏置校准；核心启发是**采集有辨识力的工况，而不只是更多随机通勤**。

它使用实际驾驶特征，7.12%不是端到端出发前结果；实路偏置还由106条中随机6条估计。论文20Hz的制动信息不能由eVED低频插值等价恢复。作者README还更正了15km/h与代码15m/s的阈值差异。许可证文件为MIT，但README另写非商业限制，两处表述不一致，不能直接宣布商业可用。我们已有G10学位论文以该路线预测驾驶特征，补读GECR是在追溯机制基础，不是又找到一个全新网络。

### 3.4 UPECT和Sequence-aware：有价值，但不能直接跑分即认为复现成功

[UPECT](https://github.com/RaganrokV/UPECT)公开处理过的小数据、训练/适配代码以及主权重的OneDrive入口；尚未验证主权重下载。其`10_Dataset_eVED.py`对电池积分取绝对值，使用实际整程时间/均速，并写入固定车辆参数；与本项目带符号PHEV净电+燃油口径不一致。VED也与我们现有来源重叠，不能当独立外部测试。全文P02尚待补齐，优先级低于输入缺失处理明确的IFS，但保留为候选。

[Sequence-aware](https://github.com/RaganrokV/Sequential_EC_prediction)公开模型脚本，未公开原始车队和完整地图输入构建链。其`GRU_SA.py`中`val_data=data_3D[train_len:]`、`test_data=data_3D[train_len+val_len:]`使公开脚本验证集包含测试集。需要修正后另行验证；这只能确认当前发布代码的问题，**不能据此断言论文结果使用了同一错误脚本**。

### 3.5 Meta-Pec与其他公开数据

[Meta-Pec](https://arxiv.org/html/2306.14421)可借鉴相似路线/时段历史检索与行为统计预测。它的ETTD是GPS推算的轮端机械能，不是实测电池电量；VED的动力类型与能量口径也混合。论文MAPE为VED 22.82%、ETTD 37.10%，本身不支持“别人都在10%以内”。代码已读取，数据下载链接存在但未验收；没有理由再次把全套网络列为第一优先级。

[TUM UDS](https://github.com/tumftm/electric-vehicle-uds-dataset)补长期电池/使用状态，已知7辆同平台车辆、超过72,000km、CC BY-NC 4.0；GPS和计划路线适配仍待核验。BMW i3/BHD可补热状态，UPECT处理件不能取代原始高频数据。以上资源均按独立任务使用，保持各自车辆、单位、时点、标签和许可。

## 4. 宏观建议：用外部证据搭建新数据基础，再定向补缺口

**首选方向：建立“已知BEV完整旅程”的新研究线，公开实测数据、外部车队知识与少量本地采集各司其职。**eVED继续完成既定基准，但不承担无法支持的完整旅程/跨车型承诺。这样直接解决目前车型少、机制信号弱、能量口径混杂的问题，也避免从零建一支大车队。

第一阶段交付不是模型排行榜，而是可用资源验收：为EnergyVille、IFS与GECR分别建立字段、单位、能量边界、缺失模式、旅程边界和划分清单。实测未来信息只作机制诊断；部署输入单独保存。优先核验EnergyVille是否能把停车/充电记录连接到下一段驾驶起点；核验IFS可否在不填入未来时间/速度的情况下正常适配。若缺关键输入或资源打不开，明确放弃该资源，不做大规模适配工程。

第二阶段只回答两个决策问题：外部车队知识能否降低我们对本地样本量的要求？可观测初始热状态能否解释仅路线/历史解释不了的差异？这是一次资源路线选择。少样本BEV评价按车辆和时间留出；与相同输入的简单模型、同结构随机初始化比较，防止把结构效应当预训练收益。热状态对照在同一数据、相同行程进行；若只有未来实际附件功率有效，则说明还缺合法预测信息，不能宣称问题已解决。

第三阶段才安排定向完整旅程采集：记录出发前导航预计时间/路线、起始热状态、停车/预调温、车型配置，以及完整电池端能量。优先重复同车同路线的冷/热、堵/畅、短/长条件，补公开数据没有配对观测的缺口。采集规模由覆盖和学习曲线决定；不预先承诺需要几百辆，也不承诺任何固定数量足以达到10%。

**第二候选方向：如果无法取得可靠车端热状态或导航快照，把输出改为场景条件下的能量预算与区间。**利用历史相似路线、天气和时间预测驾驶强度/耗时的分布，再将车辆响应与附件情景叠加。GECR、Meta-Pec、hEART交通宏观模型支持这类表示；Jiang/Choi全文将决定能否进一步采用其工况生成方案。输出区间须在独立留出上校准，报告覆盖率、宽度和低估风险。不能把宽区间包装成更准的点预测。

**目前不值得投入：继续eVED内部扩网格、全量复刻多个Transformer、盲目混合公开数据、把插值提升到10Hz当作新增物理观测。**这些路线仍围绕相同信息与标签，不能补回首尾和初始热状态；也不能把纯电轮端、电机、电池与PHEV折算总量混为一谈。

## 5. 用最少实验决定资源投入

以下是建议协议框架，尚未训练或启动队列；具体门槛须在看新测试结果前冻结。

| 决策 | 最小对照 | A意味着什么 | B意味着什么 |
|---|---|---|---|
| 是否采用外部预训练 | 共同合法字段；简单模型、随机初始化、发布预训练；固定新车未来时间留出与少样本预算 | 预训练稳定改善绝对误差和低估风险：优先扩大适配车辆，不从零预训练 | 无增益：检查标签/短途分布；兼容性排除后放弃该权重，不继续扫大模型 |
| 应新增哪些热状态观测 | 同批BEV旅程比较路线/历史、增加起始温度及停车/充电历史、未来实测热负载诊断 | 合法初始状态有效：采集这些字段；仅未来有效：发展情景/区间 | 两类都无效：降低热缺失是该数据主要误差的判断，查能量标签与路线条件 |
| 逐秒速度是否必要 | 真实驾驶强度→能量诊断，与合法信息预测驾驶强度→能量分开评价 | 少量统计已足够、且可预测：转向统计分布；减少逐秒链复杂度 | 实测统计尚不够：机制或标签有缺口；实测够而预测不够：交通信息是瓶颈 |

## 6. 七个层级的判断

| 层级 | 本轮结论 |
|---|---|
| 任务 | 分清完整旅程/裁剪片段、出发前/事后条件估计、BEV/PHEV，点值与风险同时定义 |
| 数据 | 公开机制数据可优先复用；前瞻导航快照和完整起止仍需定向采集 |
| 标签 | 明确电池净能、电机能、轮端能、SOC差、油电折算；不可直接跨库排名 |
| 信息 | 缺失嵌入借用总体先验，不能知道某次未观测驾驶/空调决策；交通与热状态有条件地补 |
| 特征 | 驾驶强度、停车/充电历史、热状态×耗时比继续堆无含义字段更有机制依据 |
| 机制 | 分离车辆响应、行驶工况和时间相关附件；明确效率/回收受SOC温度影响，不能只设常数 |
| 模型/优化 | E3/E4有局部收益；外部预训练的价值在知识来源而非模型名称；没有证据再做广泛架构搜索 |
