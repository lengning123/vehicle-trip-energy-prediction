现有路线是记录路线的离线代理，不声称已经构建在线导航系统；Oracle真实工况成绩不进入可部署排名。校准294条行程不用于训练、选模或当前主表。

## D0增强缓存

位置：`runs/route_v4_d0`，引用而不复制改写V3路段、路线输入和划分。

- 工况五维：分段耗时、停车秒数（速度<1km/h）、距离加权速度平方、正dv²和负dv²累加。复用V3原始时间积分，不用距离均分标签。
- 放电/回收：按原始功率在10Hz网格的线性插值，精确计算每小区间正/负面积，包括跨零点三角形；两者差与原净能耗一致。这里“回收”严格指电池端负功率的回充能量，PHEV中可能包含发动机充电，不能在缺乏功率来源信号时称为纯再生制动能量。
- 燃油：使用上一轮冻结标签及其来源、修正缺失记录；不重新改变MAF/RPM门控假设。
- 空调/加热：记录已观测能量和有效覆盖秒数。优先Watts列、其次kW换算；缺失不会冒充零负载。部分覆盖能量不是整个路段真实能量。
- 发动机：有效观测下的运行秒数和覆盖率，缺失有显式覆盖信息。
- 质量：原始采样间隔时间加权均值/最大值、原始点数、间隔>1秒的覆盖比例。最后一项是插值暴露代理，不是新增独立样本数。
- 首批历史扩展12项：放电/回收/燃油每公里量、停车比例、正负dv²每公里量、发动机使用率与覆盖、空调/加热均值与覆盖。它们本阶段只保存，E1仍使用原7维历史，以隔离工况作用；速度区间效率、物理残差和有效参数将在E2逐项构造/消融，不声称现在已实现全部历史建议。

检查结果：3759条、204948段未变；放电减回收对V3最大误差约5.03e-8kWh；110463段同时存在大于1e-6kWh的放电与回收。因此禁止用净值正负部充当分量。

## E1公平对照

新增一个none组，避免把改变选模方式/输入维数造成的差异算成工况收益。

| 条件 | 五维新增输入 | 身份 |
|---|---|---|
| none | 全零通道 | 同结构无工况参考 |
| rule | 路线长度/规则速度推耗时、停车0、规则v²及dv² | 部署信息基线 |
| oracle_time | 仅替换rule的耗时，其他四维保持rule | 真实耗时诊断 |
| oracle_full | 完整真实五维工况 | Oracle诊断 |
| tree | 树预测的五维工况 | 出发前预测 |
| tcn | 小型TCN预测五维工况 | 出发前预测 |

六组使用相同并行V3分段头、7维历史编码、初始状态、seed42与初始化规则。能耗当前仍为上一轮油电总能耗单头；真实预测每段再求和，E3再改变输出结构。**E1不加入新燃油/辅助/发动机监督，不以同时换历史、监督和模型掩盖信息作用。**

所有q用固定`log1p(q/[60,60,100,100,100])`变换，不以持出折标签拟合q尺度。没有新增实际速度、当前电流、油耗或质量字段作为部署输入。

## 工况预测与折外协议

- 训练2638条按车辆分层打乱，固定划为3折，粒度为完整行程。种子20260928决定划分。
- 每折用另两折拟合并预测持出折；验证/开发测试/校准的工况预测来自全训练集拟合模型，校准不参与评测。
- 每折历史统计只允许引用该折拟合集内、同车且已结束的行程，避免持出行程标签通过其他样本的历史回流。
- 输入61维：18维路线、21维初始行程特征、旧7维历史的均值/标准差/最近一次及数量共22维。
- 树模型五个独立LightGBM头，固定300棵、31叶、lr0.04、min_child_samples50、CPU2线程，log工况L1目标。
- 小型TCN：48通道、膨胀1/2/4/8，固定30轮、batch64、AdamW0.001/0.0001，log工况SmoothL1；尺度只拟合当前拟合折。
- OOF拟合不使用持出折标签选轮数或早停，因此工况预测器使用固定预算。20/5早停衰减用于后续能耗训练。若未来需要工况早停，必须新增拟合折内部验证，不能拿OOF持出折选模型。
- 预测非负，停车秒数不超过总耗时；log预测裁剪[0,8]作为固定数值稳定边界。
- 这是trip-disjoint开发协议，不冒充时间外推；时间部署实验另需时间分块重新生成OOF。

## 能耗预算与选模

完整一轮烟雾测试已覆盖144903个训练路段，约3.31秒含首次开销；据此冻结80轮最大预算、batch64、AdamW0.001、weight_decay0.0001、梯度裁剪5。全部组相同。

损失：有效路段等权的归一化SmoothL1，加整程归一化SmoothL1。sE和sTrip只由训练集RMS确定。E1不加相对误差项，留给E4控制变量。

本轮面向MAPE目标，以验证集整程总能耗MAPE（真值>0.1kWh）选模；同时保存EV/PHEV的MAE/WAPE/偏差。20次未改善停止，5次未改善学习率减半。与旧T0按MAE选模不同，因而旧结果只作背景，因果比较使用本轮none/rule等配对组。

## 阶段判断（事先固定，只用验证）

- 真实耗时相对rule的MAPE改善至少10%，且MAE恶化不超过5%：优先耗时建模。
- 完整工况相对真实耗时再改善至少5%，同样要求MAE不恶化超过5%：优先补加减速/停车信息。
- tree/tcn中按验证MAPE选候选，需相对none/rule中验证MAPE较优者改善至少2%，且MAE不恶化超过5%，才判为“预测工况有初步收益”。
- 这些是单种子工程筛选阈值，不叫统计显著。最终E6需要相同三种子及车辆簇评估。
- 若完整Oracle相对rule改善≥10%但预测版本无初步收益，先提高工况预测，不直接堆能耗网络。否则按结果进入E2，保留规则和预测参照。
