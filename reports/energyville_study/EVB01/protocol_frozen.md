## 1. EV-B01要回答什么

**名称：合法状态与历史对整程净电预算的信息价值。**

业务问题：对已知车辆和给定路线，在最初几秒读到包温后，估计走完剩余路线会净消耗多少电；把已耗前缀回加，得到该记录行程的整程预算。价值是路线电量预算与途中早期更新，不是预测下一秒功率。

这轮优先区分以下解释：

| 假设 | 当前判断 | 本实验的判别证据 |
|---|---|---|
| H1：合法状态/历史不足，运行情境信息缺失 | 缺口存在高，主导程度未定 | S−R、H−S与O−H分别判断状态、历史和未来运行的局部价值 |
| H2：标签/边界问题影响结论 | 新净量内部可用性较高，非独立真值 | 同目标的高一致性、无疑似充电、连续GPS等预定义质量切片是否改变结论 |
| H3：异构供能或分量语义妨碍研究 | 纯BEV减少油电混杂，drive/HVAC仍未认证 | 本轮固定电池净量，不能由结果宣布纯牵引/HVAC已辨识 |
| H4：任务时点/评价与业务不一致 | 高 | 同一截点预测剩余整程，回加前缀；绝对误差和低估风险同时评价 |
| H5：车辆/路线/时间覆盖不足 | 外推限制高 | 未来时间、两车、长短程及已见/新OD分层；只有两车，不检验陌生车普适性 |

它不是模型竞赛。相同学习器下新增合法信息有无收益，是下一阶段投入的依据；一次负结果不能证明该信息永远无用。

## 3. 冻结任务、标签和主样本

### 3.1 预测时点及输出

对每个源记录i：

- `t_cut = temperature_cut_prediction_utc`，等于首个可信温度桶Timestamp＋1秒。
- `t_end = end_utc`，是源记录终点。
- 主训练标签：`y_rem = temperature_cut_remaining_net_candidate_kwh`，kWh，有符号。
- 已观测前缀：`e_prefix = temperature_cut_dropped_iv_observed_net_kwh`。
- 完整记录参考：`y_full = full_source_hybrid_net_kwh`。
- 模型输出剩余量`y_hat_rem`；业务输出`y_hat_full = e_prefix + y_hat_rem`。

验证`y_full = e_prefix + y_rem`，浮点容差1e-8 kWh。回加前缀后，整程预测误差与剩余预测误差应相同。它是记录整程的早期预算更新，不是严格原始出发前，也不是已恢复真实ON/OFF旅程。

主label包含计数器与可观测IV补边近似。无需重新按旧VED的`-I×V`计算，EnergyVille电流正方向为放电。禁止abs、置零负label、固定容量×SOC替换、加入8.85燃油折算，或将drive/残差命名纯牵引/HVAC。

### 3.2 样本范围

主实验使用上述剩余候选CSV全部1272行，既有诊断有481条剩余GPS路径≥10km。不同特征组必须完全相同的ID、目标、划分与评价覆盖。

不按温度齐全、模型残差、净量大小、10km或旧0.5–64km阈值重新删样本；不要继承旧训练缓存的距离、插值、车型或PHEV门槛。若必要字段损坏/路线无法关联，保存ID及原因并在拟合前记录协议差异，不能默默改1272。

## 4. 数据准备：路线、状态与历史必须可在t_cut取得

### 4.1 剩余路线R

本轮使用实走GPS作为“给定此计划路线”的离线代理，尚无真正导航快照。不能因此声称部署导航或陌生路线泛化已验证。

使用`driving_signal_views_1s.zip`的源GPS，生成t_cut至源终点的剩余路线。**不能直接把`net_battery_route_views_1s.zip`当剩余路线**：它对应另一计数器窗口。

预算距离D以已导出的`temperature_cut_remaining_route_plausible_km`为基础；复核与截点后GPS几何的一致性，明确跨截点GPS段和未观测首尾。若重新定义边界距离，拟合前冻结新列和与旧列差异，所有组共用；不能为个别组选择距离。

R的最小白名单：车辆ID one-hot、D、剩余路线起终点经纬度、直线距离、路线/直线距离比及未定义标记、整体方向sin/cos、纯空间几何转向统计。几何先去连续重复点并按**等距离50m**重采样，禁止用每秒点数、GPS采样数、每段耗时或停点数量编码实际速度。

本轮不要求先完成全套Belgium道路/高程外部接入。若已有合法静态地图缓存，可在冻结前统一加入高差、正负坡度、道路类型/限速/路口属性；记录来源和版本，全部模型组共用。没有就执行几何版，明确未检验完整道路信息，不能将负结果归为“路线信息没有用”。地图缺失不能用未来速度冒充限速。

### 4.2 起始状态S

所有信号在一个1秒均值桶结束后才可用：**bucket_timestamp＋1秒≤t_cut**。对每个信号分别向过去取最近有效值，保存观测时刻、年龄和缺失标记；不以缺SOC/外温删行，不向过去填未来值。

最小S白名单：最近SOC、外温`VCRIGHT_tempAmbientRaw`（缺失再用`VCFRONT_tempAmbient`并标来源）、包温min/max及差、预调温请求`UI_batteryPreconditioningRequest`（若有效）、各观测年龄与缺失标记。包温可用已验证的`temperature_cut_min_temperature`/`temperature_cut_max_temperature`，但复核其桶已结束。

SOC限[0,100]、包温沿用R05有效范围；无值保留NaN和missing。年龄不代替真值。跨模式冲突保留标记，不能平均未来同桶量作为起点状态。

按物理关系预先允许少量交互：`D×(外温−20)`、`SOC×包温min`。它们是表示选择，不是已识别因果或厂家控制阈值；不施加总能耗随速度/温度的全局单调性。本轮不把前缀IV/功率用于学习器，`e_prefix`仅用于最终预算回加，所有组一致。

### 4.3 合法过去历史H

主协议为**训练期历史冻结**：历史label来源只能是训练区间内、同车、`source_end＋1秒≤当前t_cut`且质量合格的已完成源记录。训练样本也逐条排除自己和所有后来样本；验证、校准、未来留出的label不得进入任何历史库。执行首轮不滚动读测试真值。

历史可用完整源hybrid净量与它自己的源路线距离，不将不同时间边界的能量和距离混用。历史池从主关联表中选：完整源hybrid可得、内部一致性通过、无明确外充/同桶冲突，且属于训练ID；保留历史pool实际数量。历史时长来自已经完成的source，可以用，但只能是过去记录。

最多最近10条同车记录，H白名单：可用条数、最近结束距当前秒数、历史净量/距离的合计比、历史Wh/km中位数、历史距离和时长均值、历史均速代理、过去外温/包温摘要、各缺失标记。Wh/km的单条分母只在距离>0时定义，合计比用`sum E/sum D`，无历史保留NaN，不用当前真实能量补值。

增加一组粗OD历史摘要：起终点分别落入固定250m空间网格，方向保留，长度按1km分箱；同车同key的已完成训练历史条数、净耗电率、时长均值。key仅用路线几何定义，不用能耗聚类；它是粗OD代理，不证明道路路径相同，不称严格route-disjoint。

历史温度遥测可来自截点前已结束的桶（含停车/充电模式），但当前样本的未来桶禁止。注意**遥测历史**和**历史能量label池**是两类权限；后者必须训练ID且整个source结束，不能拿进行中会话的最终量。

### 4.4 一律禁止进入合法模型的列

当前剩余/完整行程实际耗时、均速、速度强度、停驶比例、全程温度/控制汇总、未来IV、未来累计量、drive/regen增量、任何当前label及由其反推的距离/率。当前全程质量覆盖、外充证据、首尾漏边、文件结束时刻只用于资格/报告，不作特征。

源Timestamp真实采集时区未完全认证：本轮用统一发布计算轴做排序，不猜匹配历史天气，不把它包装成本地小时/交通实况。日内/星期时间特征本轮不加入。

生成全新的特征白名单，禁止“主表删几个target列后全喂模型”。中位数填补、one-hot词表/缩放/聚类/可选地图统计只在训练期拟合；未见类别保留unknown。missing列必须由允许的输入构造。

## 6. 五组对照，固定学习器

| 组 | 输入/计算 | 验证的问题 |
|---|---|---|
| B0 | 每车训练期`sum(y_rem)/sum(D)`×当前D；缺车回退训练总体率 | 简单距离预算能做到多少 |
| R | 路线R＋车辆 | 路线与车辆条件能否超越单一单位里程率 |
| S | R＋合法起始状态S | 初始SOC/外温/包温等观测能否增加信息 |
| H | S＋合法历史H | 已知车既往使用/粗OD历史能否减少未知运行情境 |
| O | H＋真实剩余耗时/运动统计，标Oracle | 当前未来运行缺口在这个固定学习器中是否还有明显可利用价值 |

R/S/H/O同样预测kWh。推荐以B0作距离载体，学习残差：`r = y_rem−B0`，`y_hat_rem = B0 + f(X)`；不同组只有输入块变化。这样预算有距离尺度，避免树直接回归kWh时完全没有线性外推。B0各系数只能用训练label估计，所有组一致。

本轮默认复用项目强树路线中的`HistGradientBoostingRegressor`学习器，**新建EnergyVille数据适配，不直接调用旧prepare_v3读取eVED**。

固定配置：`loss='absolute_error'`，`learning_rate=0.05`，`max_iter=500`，`max_leaf_nodes=31`，`min_samples_leaf=20`，`l2_regularization=1.0`，`early_stopping=False`，`random_state=42`；车辆one-hot，输入缺值保留或训练期填补＋missing，四组处理一致。使用整程L1损失，标签不作log/abs，输出不裁非负。

旧脚本的自动early_stopping可能划出随机内部验证，本轮明确关闭。上述确定配置不需要重复三种子制造稳定性；预算为四次模型拟合＋B0，不做模型/超参数网格。默认CPU执行，云端资源参数由执行窗口按现有环境设置，记录版本/线程/资源/耗时，不要求新增GPU算例。

若云端缺该学习器或API不兼容，先记录实际版本并解决适配；确需换固定等价树模型，在首次拟合前写明唯一配置及原因，所有组同换。不是从多个模型挑最优。

O的未来变量单独保存在Oracle白名单中，绝不混入合法模型：

- `actual_remaining_duration_s = t_end−t_cut`。
- 根据当前剩余GPS的真实时间间隔计算运动速度；仅相邻有效GPS、0<dt≤2秒、速度≤200km/h的区间参与。计算距离加权速度平方、可观测停驶时长比例（v<0.5m/s）与覆盖/缺失标记。
- GPS缺口不线性补全运动；不能未经单位确认把`DI_uiSpeed`称km/h。Oracle缺覆盖保留missing，不为O另删行。
- 不加入IV、累计能量、SOC终点或直接组成target的量；否则是目标泄漏，不是有意义的Oracle。

Oracle只是本学习器对所给未来运行统计的诊断，不是理论误差下界；O无益不能否定所有未观测信息。

- feature whitelist没有当前target、未来列或由target构造的变量；Oracle列单独隔离；四学习组采用相同label和ID。
- 类别/填补/标准化等只fit训练；禁止按全表min-max或用未来label做历史。
- pandas秒数用时间差`.dt.total_seconds()`或显式纳秒单位，避免默认微秒整数除1e9造成1000倍错误。
- 从短/中/长各抽一个source，人工/脚本复核t_cut、已结束桶、路线范围、label单位与已耗前缀。

发现可修复实现错误应修复并留痕。无法明确label或因果边界时，记录阻塞和具体ID，不启动正式拟合掩盖它。

## 8. 评价与预先指定的决策规则

### 8.1 指标和质量切片

主指标：未来整程kWh MAE。同步报告RMSE、偏差`mean(pred−true)`、WAPE（分母`sum|true|`）、两个车辆宏平均MAE及每车MAE。

低估风险：`mean(max(true−pred,0))`、低估量95分位。剩余与回加后的整程都输出；两个MAE应相同，MAPE可能不同。

MAPE仅对`true>0.1kWh`计算，报告分母与覆盖；主评价保留所有有效小/零/负标签。不把MAPE<10%作为首轮成功要求。计数器4Wh保守量化尺度与净量之比只是量测分层，不是预测误差界。

固定报告切片：两车；D<2、2–10、10–50、≥50km；粗OD已见/未见；无/有历史；外温<10/10–25/>25℃与缺失；疑似充电/模式标志；>2秒日志缺口；内部一致性通过/未通过；计数器量化尺度≤5%/其他。所有切片规则在拟合前定义，样本<20只描述。

敏感性仅在同一已冻结预测上重新计分，不重训、不改主样本：排除`uncertain_charger_signal_or_mode_overlap`；仅内部一致性；仅无>2秒缺口；仅满足5%量化尺度。标记这些是源标签质量代理，remaining额外包含IV补边近似，不能称精确remaining误差上限。子集指标变好不是完整任务模型改善。

### 8.2 验证选择与投入阈值

验证集先比较B0/R，取MAE较低者为基础预算参考；比较S/H，取较低者为合法信息候选。MAE相差≤1%时选较简单者。O只诊断、不参加业务模型选择；未来留出不重新决定名次。

继续投入合法信息的**工程研究门槛**：候选相对基础参考验证MAE至少改善10%，整体RMSE不恶化>5%，每车及≥10km层MAE不恶化>10%，平均低估量不恶化>5%。基准指标接近0时改报绝对差并标门槛不可稳定判定，不编造比值。这些不是业务验收容差或统计显著性。

局部归因必须保留R→S、S→H、H→O的配对差，不能只拿最终最佳值说温度/历史有效；S块含多种状态，本轮不能把S收益全归为包温。

未来留出对配对误差差做**同一日历周整块bootstrap 1000次**（两车同周一起，固定seed42），报告样本/周块数与95%区间。少于8个周块不作稳健区间结论，仅报告点差和局限；这始终是两辆车的时间样本不确定性，不是车队泛化置信区间。区间跨0表示未建立稳定优越，不表示等效/信息无用。

### 8.3 结果意味着什么

| 实际模式 | 多知道了什么 | 下一步方向 |
|---|---|---|
| S/R或H/S通过验证门槛，固定未来留出改善也保持 | 合法状态/历史在新目标下有可推广信息，原始数据重构值得 | 优先完善同路线条件预算与独立校准，再分边界验证第二公开源；不是先换网络 |
| O明显胜H及最优合法组，而合法新增块无稳定收益 | 已测未来运行在当前映射有价值，合法代理尚不足 | 研究历史交通/驾驶情景与预算区间；不承诺恢复唯一未来轨迹 |
| 所有组无稳健收益，训练也拟合不好或预检有问题 | 信息、表示、训练/标签尚未区分 | 先核查单位、对齐、可利用性和固定学习器，不宣布不可预测 |
| 训练好、验证/未来明显退化，长程/新OD集中 | 时间/路线覆盖或外推更可疑 | 检查分布偏移与路线代理，扩大条件范围验证而非盲目加网络 |
| 高质量切片改善明显，主库不改善 | 标签/边界/归属的证据增强但有场景混杂 | 回查具体源机制；不按大模型残差删困难样本 |
| B0已接近其余模型 | 对当前两车，距离基准已强或新增信息未被利用 | 报告可用简单预算和剩余误差结构，停止不必要复杂化；不宣称领域机制无效 |

不要强行把结果归入单一假设；同时报告支持、反证、缺证。跨新BEV和旧PHEV分数不做性能提升比较。
