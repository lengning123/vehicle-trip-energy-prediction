日期：2026-09-30。Research Manager负责方向与验收，三个子agent分别完成数据处理、独立标签核验、文献分析。原公开ZIP只读；本轮没有训练模型。

## 管理者摘要

已保留1396驾驶源记录：1359条计数器路线候选、1320条内部一致性核心、1284条完整源补边标签、1272条首温后剩余量标签。所有记录前6秒都有包温，原436限制过早。主线转已知BEV的整程净电量预算，支持短观测后更新；放电/回充保留分量。瓶颈是输入时点、运行情境、标签语义与两车覆盖。纯驱动/HVAC尚无独立边界，暂停伪分量标签和换网络。

## 1. 这轮纠正了什么

温度对热管理和回收机制重要，但不是电量标签能否量测的条件。我之前以“首行包温可得”收窄共同集到436，混淆了输入与标签资格；这个限制取消。首桶有温度477条，而**1396条内部全部有可信温度，首个值延迟中位1秒、95分位3秒、最大6秒**。

用户提出的首温截断可行。等待该1秒桶结束后再开始预测，损失中位2秒、95分位4秒、最大7秒；GPS可观测路程损失95分位10.70m，有符号IV净量损失95分位3.459Wh。该分位数不是最大值或独立量测误差上限，不能据此说冷启动没有能耗。完整源记录保留，截断版本命名为剩余记录行程；首温不填回原起点。

全量2310会话、6,722,917行已处理。驾驶1396、停车780、慢充109、快充25；发布件是1秒均值CSV，只有一个原始MF4示例，不宣称获得全部原始CAN。所有文件有去向。里程哨兵、缺口、运动、重叠、充电证据与温度分别标记，避免把不同问题绑成一个共同删除条件。

### 主标签为什么选净电池支出

EnergyVille电流正方向为放电，IV诊断使用 `P=V×I/1000`。主参考 `E=ΔTotalDischargeKWh3D2−ΔTotalChargeKWh3D2`，单位kWh，不取绝对值。在无外部充电的驾驶区间，流回电池的能量主要是再生回充。该量直接回答“这段路线净花掉多少电”，服务路线电量预算；它不是电网购电、固定容量×SOC降幅或轮端机械功。

纯计数器参考实际漏头中位1秒、95分位3秒、最多5秒，漏尾中位/95分位/最多1秒。因此计数器窗口表对齐该范围；原source完整标签另用有符号IV补边，补边覆盖≥99%且计数器端点同步才给值。两种标签分别命名，不把局部IV积分冒充跨缺口全量。该补边及remaining标签属于显式测量近似，后续评价保留不确定性。

基础计数器标签1375条；加入运动、路线、模式与冲突规则后1359条，恢复894条首桶无温记录。1320条同窗IV覆盖≥99%，差值通过 `|IV−counter|≤0.02kWh+0.03|E|` 工程一致性规则。1295条同时满足保守量化界不超过净量5%。这两种阈值不代表模型误差或仪器校准精度；小/负净量仍留全表，主要评价kWh误差、偏差与低估，百分比指标只做明确覆盖的辅助分层。

### 为什么暂不选纯驱动或纯负载

用户允许有文献意义的整程分量，这是合理的。问题在于当前字段没有给足独立测量边界：BMS drive与regen多路复用，组合端点异步中位11秒，不能机械相减并称精确完整源驱动量。同名义窗口/as-of的T/D中位约99.44%，615条非驱动残差在±10Wh内；仍不能据此认证T是独立电机支路或残差是HVAC。

静止驾驶块中计数器也增长：512源记录的1964个60秒块里，速度≥90%可观测且全0，1917块T增量≥5Wh。这排除T等于轮端机械功，不能仅凭这一点认定是哪一附件。全部T/R及余项按[标签合同](label_audit/推荐标签契约.md)保留候选；纯牵引、空调、加热能量暂不成立为高可信主标签。

文献确有整程分量任务：[Zhu，TTE，电机VI积分](https://doi.org/10.1109/TTE.2024.3416532)在缺HVAC时选择电机电能；[Kim，Applied Energy](https://doi.org/10.1016/j.apenergy.2025.126766)研究附件预算但以电池电能减机械功定义残差。前者不能证明我们BMS drive就是同一电表，后者的边界含转换损耗是物理推断。EnergyVille [Scientific Data原文](https://doi.org/10.1038/s41597-025-06148-5)及Fig.12/13支持驾驶电池电量预算；Fig.15累计分类不构成逐程HVAC独立计量认证。详细全文页码、用途、可用资源见[文献与方向报告](literature/整程分量标签的价值与文献依据.md)。

## 3. 学到了什么，而不只是增加了样本

- **首温不是主要数据缺失。** 发布首行缺值多数是广播时点，温度在几秒内可得。严格原起点输入与观测完成后的输入是两个任务时点；信息问题应以合法时点处理，不能当标签删除条件。
- **计数器有价值，边界须分开。** 累计量可覆盖部分日志缺口；纯积分无法。主候选65条有>2秒缺口，仍保留缺口/路线质量；>60秒或严重缺边为候选层，不当完整物理旅程。
- **字段名不等于分量真值。** 实物数据不足以把drive与aux词语转成纯牵引/HVAC标签。换label可以有业务价值，但不应制造机制解释。
- **单字段充电/区间重叠不等于坏旅程。** 宽规则86条疑似与10条联合/计数器外充证据不同。77条自有充电字段命中多为短促电流/电压而功率0、相应桶电池未充入。主库保留70条待确认信号/模式迹象，另给1289条敏感性视图。重复模式副本按驾驶区间拥有一次，冲突另标。
- **增量来自恢复和合同，不来自插值造独立样本。** 两车仍是两车；百万秒不证明泛化。新BEV基准不能作为原PHEV模型成绩提高。

## 4. 宏观建议与下一份判别证据

**首选：重新建立“已知BEV、给定路线的整程净电量预算”任务。** 原混合PHEV油电估算保留为历史基准，新线以可追溯电池量测为核心。完整记录标签供严格起点研究；用户允许的短起始观测版本给出 `整程预算=已观测前缀+剩余全路线预测`，主remaining候选1272条。这是改变信息合同并利用真实配对数据，不是继续替旧任务换网络。用途仍是一次路线的电量预算，真实ON/OFF与导航部署不在本轮证明范围。

**第二候选：同路线条件能量分布与预算更新。** 用已结束的同车/重复路线历史形成不同交通/热状态情景；停车/充电只提供过去状态证据。若合法输入不能支持唯一精确值，给校准预算区间和低估风险，不宣布已测得不可约误差。首温remaining也可以回加前缀，单独评价观测后的整程更新，不混为严格出发前。

**目前不值得：把D−T称纯HVAC、异构表直接混库、扩大网络网格。** 这些没有解决量测语义、预测时点和运行情境，可能把无独立真值的残差当成监督。

下一轮只做有决策价值的对照：冻结同一标签/预测截点、未来时间块及路线分组，比较路线/车辆基准与加入合法过去状态的预算；未来实际耗时/速度另作Oracle诊断。合法状态有效且未来块保持收益则推进；只有未来有效则转历史情景/区间；均无效则查边界和覆盖，不自动搜索结构。remaining与完整源是两套目标边界，不能跨边界比较分数宣布提升。

| 层级 | 这轮决定 |
|---|---|
| 任务 | 已知BEV整程净量；明确严格起点与短观测后预算更新 |
| 数据/标签 | 全源保留、计数器参考、同步IV补边、路线同窗、分层质量 |
| 信息 | 温度可缺失/带年龄；首温桶结束才可用，未来实际运行只诊断 |
| 特征 | 计划路线代理、过去状态/情景；不直接用主表所有诊断列训练 |
| 机制 | 放电/回充与热/时间关系；不把分类计数器认作部件电表 |
| 模型 | 简单路线/历史基准先判断新增信息，不优先深模型 |
| 优化 | 同窗整程绝对误差、偏差、量化覆盖与条件低估；不靠小分母删行 |
