更新：2026-09-30。研究上下文入口；每轮开始依次阅读本文件、[根因假设](hypotheses.md)、[实验记录](experiments.md)、[决策记录](decision_log.md)。本次在6篇全文基础上验收UPECT四份实际数据与EnergyVille全包，按用户“仅能使用网上公开数据”约束修订D10；未新增训练，未修改既有实验协议或结果。

## 管理者摘要


资源约束改为只用网上公开数据。UPECT四加工表共5294条，不能直接替代原库：未来统计、标签边界和信息丢失是关键问题。EnergyVille全包已读，1396驾驶文件有GPS/IV/热状态；初步436候选通过基础检查，194条≥10km。首选重构独立BEV会话基准，第二候选分源历史预算与校准区间；暂停异构混库和换网络。真实ON/OFF、导航快照和PHEV燃油真值仍未补齐。

## 0. 当前主线：只用公开原始数据，重建可解释的BEV会话基准

2026-09-30 D10替代D09的资源安排。用户明确没有可接入车辆、设备或合作资源，所以**自采/校企合作退出当前可执行主线**。现有PHEV油电基准和M3-relative参考保留；建议另建BEV研究线，不用新BEV分数声称原目标已解决。[公开数据验收](reports/public_dataset_audit_20260930/公开数据路线与UPECT验收.md)记录字段、哈希、统计、限制和方案。

### 最值得推进的宏观方向

**公开原始信号→统一测量边界→严格起点信息→分源验证。**优先EnergyVille V2：完整发布包已下载，全2310会话CSV已读取，其中1396驾驶文件、780停车、109慢充、25快充；两辆已知Tesla Model Y。发布会话是1秒均值处理件，只有一个原始MF4示例；实际字段包含GPS、IV、SOC、外温、包温、预调温请求与累计充放电计数器，能够增加真实信息，而不只是增加同类短片段。

第一阶段研究对象建议命名“给定路线的已知BEV会话净电能预算”。在缺ON/OFF和真实导航快照时，不宣称真实出发到停车的完整旅程已解决。实走GPS仅是计划路线已知的离线代理，实际耗时/均速/未来负载不回填输入；严格截点使用已结束的测量桶与过去历史。

已经生成[1396行候选表](reports/public_dataset_audit_20260930/energyville_candidate_trip_table.csv)。初步436个候选同时具备首行包温、SOC/外温，并通过时间/IV/GPS基础检查与无重叠检查，其中194个GPS路径≥10km。**候选数不等于最终合格旅程数。**发布数据含85个>2秒缺口驾驶文件、26个与其他模式会话重叠驾驶文件、异常里程计；首行包温仅477/1396可得。边界、短会话、GPS抖动、时点合法性仍待验收，不能直接启动训练或承诺精度。

### 第二候选和暂不投入方向

第二候选是分公开源的机制/迁移验证与历史条件预算区间。原始BHD补BMW电热信号，TUM/EVE补热与停车历史机制，DEVRT待验小型路线/交通对照，GECR补驾驶响应。来源和目标边界分别保留；不把不同车的字段拼成同一旅程。IFS/UPECT权重降低训练需求的可能性仍保留，排序低于原始数据验收，需同合法输入控制。

不直接合并UPECT四表或仿真库，不把实际时间/速度充作导航预计值，不重新开网络/超参数网格。UPECT的69 BHD、132 ChargeCar、4599 SpritMonitor、494 VED是加工记录，标签和样本单位不一致，均无原始路线轨迹；VED与现有库同源，不能当独立外部验证。预训练30多万原始行程不公开。

### 原问题在公开条件下怎么解决

| 原问题 | 当前可做的公开数据处理 | 未解决边界 |
|---|---|---|
| 首尾裁剪/冷启动 | 用EnergyVille连续多模式日志重建运动、停车、充电边界，保存测量与缺口 | 无ON/OFF不恢复确定完整旅程，保留“记录会话”定义 |
| 油电标签不稳 | BEV新线用有符号IV与累计计数器交叉核验；原PHEV做敏感性、来源分层 | 本轮资源无独立燃油参考，不能修成PHEV真值 |
| 缺出发交通 | 同车同路线训练期历史时长/强度分布；DEVRT仅待验外部诊断 | 今天API不能补过去导航快照；未来实况仅Oracle |
| 缺热状态/附件 | EnergyVille同车包温/预调温与已结束会话；BHD/TUM/EVE分源研究 | 不用出发后首个有效值回填，不把电池减驱动残差视作独立HVAC真值 |
| 匿名车/覆盖少 | 新增两辆已知车与长短程，逐源验收车型和质量覆盖 | 仍小车队，不能以百万秒记录证明普适或季节全覆盖 |
| 相同输入多种结果 | 固定车辆/路线检查条件波动，分位数预算和独立校准 | 不宣称已测得不可约误差或10%下界 |

数据应分车辆配置、原始会话/标签、预测截点输入/历史三类可关联对象，保留原值、单位、测量来源、有效年龄、缺失及质量标记。标签侧跨长缺口不积分、不取绝对值；计数器与IV来自同车内量测链，一致性不等于独立真值认证。EnergyVille电流方向与VED不同，采用逐来源符号合同，不把原`-I×V`公式机械套用。

最有信息价值的下一步是边界与合法起点验收后，在同批共同样本比较简单路线/历史基线与新增合法热状态；未来实际耗时/负载另做匹配重训Oracle。合法新信息有效才扩展第二公开源；只有未来有效则转情景/区间；都无效则回查边界/标签/覆盖。新训练前冻结输入、标签与未来时间/路线划分。

仅网上公开数据的限制意味着：我们可以改善可观测条件并理解误差来源，但本轮没有发现能同时提供独立PHEV燃油真值、真实ON/OFF和出发导航快照的齐套源。若原业务要求这些条件，当前不能承诺全部解决；研究成果必须明确条件范围。

## 1. 真正要解决的问题

在车辆尚未走完所给路线、只知道路线、起始状态和已完成历史的条件下，估计这一段路线会消耗多少电和油。用途是支持出行能量预算与路线决策；目前只验证离线估计，尚未验证导航路线选择、缺电风险或实际续航决策的收益。

这不是“已知道实际速度后重建功率”，也不是“用前60秒预测后10秒”。后两者可用于诊断，但不能替代当前任务。我们需要学习的是可用信息条件下的能耗分布；同样路线和起始SOC不保证唯一能耗。尚未量化剩余随机性，不能宣称到达不可突破的误差下限。

### 当前目标必须分开命名

| 对象 | 标签/输出 | 可以说明什么 |
|---|---|---|
| EV | 带符号电池端净电量，kWh | 记录片段内的净电池支出；不含外部充电损耗 |
| PHEV电池 | 带符号电池端净电量，kWh | 电池支出与回充的净额，受发动机供能策略影响 |
| PHEV燃油 | 估算燃油体积，L | Fuel Rate或MAF推算结果，非独立量热真值 |
| 当前PHEV总量 | 电池净电量 + 8.85 kWh/L × 燃油L | 冻结的油电折算能量口径，不是轮端机械功、费用或碳排放 |

电池功率采用 `P_batt(kW) = -I(A) × V(V) / 1000`，按实测时间积分。V4分量为放电 `D=∫max(P_batt,0)dt`、回充 `R=∫max(-P_batt,0)dt`，满足 `E_batt=D-R`。PHEV回充可能来自发动机，不能统称再生制动。总量保留带符号值；更换目标不构成模型性能提升。

8.85是本项目冻结折算系数，不代表每辆车实测燃料热值。电池端与燃料端边界不同，跨EV/PHEV比较效率时必须说明；PHEV总量不能单独回答“还剩多少电”。后续应同时提供电池、燃油和总量，是否转为概率区间或按工况拆任务由诊断证据决定，不擅自替换目标。

### “整程”和“出发前”的现实边界

缓存manifest明确是 `full-recorded-trip`。VED原论文说明公开轨迹经过首尾隐私裁剪、地理围栏和主要路口边界处理；eVED是在VED记录上做地图增强。**因此当前整程指公开记录片段的完整时间轴，不保证涵盖真实点火至熄火旅程。**这一边界得到来源和本地manifest支持；每条记录裁掉多少、是否已经热车，当前未知。[VED原论文，III节](https://arxiv.org/html/1905.02081)、[eVED原论文](https://arxiv.org/html/2203.08630)

由此提出而尚未证实的解释：片段首点SOC/外温可能不足以描述发动机、电池和座舱热状态；记录起点不等于冷启动。路线本身又由实际走过的GPS匹配得到，是“计划路线已知”的离线代理。尚未验证路线偏离，也未证明全部地图属性可按历史时点在出发前重建。

## 3. 目前模型为什么可能做不好

1. **运行情境不完整。** 限速和路口数量不能确定排队秒数、红灯相位、驾驶操作和热负载。耗时影响附件能量，但仅知道耗时仍不知道负载功率。
2. **需求与供能不是同一件事。** 路线动力学描述车轮需要多少功；PHEV由电池还是发动机供给、是否同时充电、效率和热机过程还要另解释。总量折算也没有消除这些差异。
3. **目标本身有估算误差。** 原始采样间隔、燃油修正缺失、RPM/MAF不同步等可能让模型在拟合不稳定标签。
4. **优化的量与决策的量不一致。** 路段MAE低不保证整程求和准确；MAPE又放大小能量行程的重要性。高估和低估可能相互抵消，不能用总误差小证明分量正确。
5. **覆盖不足。** 27辆车、3辆EV和大量短路线，不能用二十万路段代替多车辆、多工况证据。

我的判断：**任务定义/标签与信息缺失优先；机制和覆盖其次；特征表达与目标对齐需要受控验证；没有足够证据把主要瓶颈放在网络规模或普遍训练不足。**这是研究优先级，不是已完成的因果分解，五项可证伪假设见[hypotheses.md](hypotheses.md)。

## 4. 领域机制与理论预期

简化车轮需求为 `F ≈ m·a + m·g·Crr + 0.5·ρ·CdA·v_rel² + m·g·sin(坡度)`。电驱供能还需区分正牵引效率、制动回收限制和附件功率。车辆参数与速度时间轨迹共同决定能量流，这是FASTSim官方模型的基本组织方式。[FASTSim官方说明](https://natlabrockies.github.io/fastsim/getting-started/)

以下为据力学作出的条件推导，不是本项目已估计的因果系数：

| 理论预期 | 对建模的约束/可检验诊断 |
|---|---|
| 固定路线与其他条件，提高高速行驶速度会增加单位距离风阻能量（无风近似随v²） | 整程均速不能代替距离加权v²；不能对总电耗施加无条件速度单调性，慢行会增加附件工作时间 |
| 附件能量约为平均附件功率×耗时 | 优先检验耗时×HVAC/温度/热状态交互；停车距离近零不代表耗能近零 |
| 同净高差的上下坡与平路能耗未必相同 | 驱动/回收效率不对称，保留正负能流；不能用平均坡度覆盖全部机制 |
| 更重车辆在其他条件相同时增加滚阻和加速需求 | 载荷缺失可能形成条件残差；历史等效系数不等于辨识出真实质量 |
| PHEV发动机介入受电池状态、动力需求和热负载影响 | 不能预设初始SOC与总量全局单调；应检查SOC×温度×运行需求交互 |

PHEV发动机可参与驱动和电池充电；电池不足、加速和较强热负载都可能触发介入，支持把需求与供能分开考虑。[美国能源部AFDC](https://afdc.energy.gov/vehicles/electric-basics-phev)

限速、设施密度、外温、历史均值主要是代理变量：分别代理可能的运行速度、起停机会、热负载和既往车辆/驾驶情境，不能将特征重要性解释为真实因果。电池高SOC/温度对回充限制的具体阈值、冷机效率和空调控制规律需要车型技术资料，当前没有可用的逐车型可靠参数；不猜数值或用统一Leaf参数冒充真实PHEV机制。

燃油估算沿用Fuel Rate优先、MAF回退；原论文给出E10空燃比14.08及STFT/LTFT修正，动态空燃比不可得。745g/L、缺失修正归零和MAF分支RPM门控是本项目显式工程假设，不能统称论文真值。[VED原论文，Algorithm 1](https://arxiv.org/html/1905.02081)

阶段筛选只按冻结验证门槛；最终确认需相同信息、目标、划分及可比预算的强基线、多种子和车辆簇配对不确定性。外部检验决定能否外推；业务上可接受的绝对误差、低估风险与计算成本尚未量化，不能把论文单一指标当作业务验收。

## 6. 持续维护规则

每轮由Research Manager主动提出判别性最强的下一步。结束时先给≤300字摘要，再写做了什么、学到了什么、因此做什么；更新五个假设的支持/反证/缺证和置信变化。实验记录追加可追溯事实，当前理解和假设则修订到最新状态；已否定的旧结论保留历史并标明失效原因。启动新实验前完成七层检查，不能把上一轮的“下一步”机械执行成无限队列。
