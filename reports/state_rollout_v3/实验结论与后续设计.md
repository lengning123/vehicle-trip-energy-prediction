# 三组状态递推实验：结果、解释与后续设计

更新：2026-09-26。三组×三个随机种子共9次训练全部完成。九份权重、配置、训练日志和训练后预测已同步本地。全部在36–85轮间由20轮未提升早停结束；训练与逐轮验证合计约49.8分钟。

本轮结果支持把**隐状态递归作为后续开发的主要参考结构**。显式状态反馈具有合理性，但当前实现没有进一步降低平均整程误差。完整数字见[自动对照报告](三组状态递推对照报告.md)，分组见[误差结构分析](分组与误差结构分析.md)，冻结模型干预见[状态反馈诊断](状态反馈诊断.md)。

## 1. 三组实际结果

所有指标来自相同539条测试行程；“±”为三个训练种子的样本标准差。

|方法|整程MAE（kWh）|RMSE（kWh）|分段MAE（kWh）|整程耗时MAE（秒）|平均训练+逐轮验证耗时|
|---|---:|---:|---:|---:|---:|
|并行路段预测|0.1854±0.0034|0.3206|0.01712|263.4|78.6秒|
|仅隐状态递归|0.1768±0.0013|0.3019|0.01749|257.7|351.5秒|
|显式状态递归|0.1785±0.0010|0.3046|0.01747|254.8|565.2秒|

隐状态组比并行组的平均MAE降低4.62%；显式组降低3.70%。显式组比隐状态组高0.0017 kWh（约0.97%），三个种子中的方向一致。不过车辆和训练种子的配对区间仍覆盖零，应将这些结果理解为当前数据上的方向性证据。

两种递归组使用相同GRU结构。它们名义参数量相同，但hidden关闭的状态支路权重没有梯度；并行组参数更少。三个组共用分段监督和能耗求和输出，因此hidden对explicit最直接回答“显式累计状态是否提供额外价值”。旧V3直接整程模型采用不同监督与输出头，不能把跨版本差距全归因于递推。

## 2. 递归带来了什么

递归模型的整程误差下降，分段MAE却略升。隐状态组的整程有符号偏差由并行组的−0.0300改善到−0.0111 kWh；分段正负误差积分后的未抵消比例由0.207降至0.193。这与模型更好地协调跨段输出相一致，但不能据此声称每段的功率或能耗解释更精确。

显式组的有符号偏差进一步接近零（−0.0032 kWh），耗时MAE也略低，却没有超过隐状态组的整程MAE。减小整体偏差不一定同时减小逐行程绝对误差。

分组结果显示收益并不均匀：2–5 km的270条行程中hidden最好；5–10 km的37条行程中并行组反而最好。EV子群中explicit点估计最低，但测试中仅有2辆EV、71条行程。没有≥10 km测试行程，不能把本轮结果外推成“长行程越长，递归收益越大”。

## 3. 显式反馈为何没有继续改善

以下结论结合指标与验证集干预，区分已观测事实和解释假设：

- **模型使用了反馈，但依赖较弱。**保持权重不变，屏蔽累计/上一段能耗后，验证MAE平均只增加约0.0010 kWh；屏蔽时间/时刻增加约0.0004。状态支路没有完全失效，但其贡献有限。
- **反馈中的耗时估计质量较差。**显式组预测总耗时约为实际的57.2%，进入路段的时刻平均绝对误差约128.5秒。把真实前段耗时替换进冻结模型，验证MAE仅改善约0.0001 kWh，说明时间误差目前并未被能耗头有效利用；单独提高时间精度未必自动改善能耗。
- **隐状态和显式累计量可能重复表达部分信息。**已用能耗、前段输出、路线进度都可由前面的预测或已知路线推导；GRU本身已有记忆。干预结果支持“新增支路的边际作用较弱”，但需重新训练消融才能区分信息冗余和融合方式不合适。
- **本轮尚未实现SOC/电池温度等动力学状态更新。**动态SOC需要可靠容量或状态转移校准。这里检验的是累计能耗、耗时等预测反馈，不能据此否定更完整的车辆状态模型。

真实反馈干预仅用于288条验证行程，属于不可部署的诊断。模型原本在自身预测上训练，换成真实状态也会造成分布变化，所以真实反馈不构成性能上界。诊断在本地FP32执行，正式训练为云端TF32；验证MAE运行时差异约0.000005–0.000018 kWh，已逐种子记录，未改写正式测试结果。

## 4. 耗时头的具体问题

已核验分段耗时之和等于原始行程持续时间，标签没有遗漏停车时间。停车时间占测试总耗时24.5%，但含至少1秒停车的路段仅占7.9%；显式组对这些路段的预测总耗时仅为实际的13.8%，它们贡献了约56.4%的总低估量。其余路段的预测/实际耗时比为81.9%。

当前输出形式为规则耗时乘有界指数，最大为规则耗时×exp(3)。0.6%的路段标签超过此上限，超限部分占实际总耗时5.7%，是明确的表示限制。其余低估可能与长尾停车时长、逐段log-Huber目标和能耗主任务选模有关；这部分原因需要新的验证实验确认。

## 5. 后续设计优先级

1. **先改耗时建模。**拆成行驶耗时和停车耗时：由路线条件预测行驶速度，同时预测停车概率及条件停车时长；使用无固定硬上限的正值输出。增加整程耗时一致性/误差项，避免仅优化逐段对数误差时整体时长系统性偏低。
2. **将显式状态通过可学习门控注入GRU。**以较小初始门控引入状态，对累计量、前段局部量分别做消融；比较能耗反馈、耗时反馈及二者组合。需要重新训练这些组，不能把本次冻结权重屏蔽当作已完成的训练消融。
3. **让时间和车辆状态影响有明确含义的能耗分量。**例如将预测耗时用于历史条件下的辅助负载分量，保留带符号驱动/回收部分。SOC递推应在容量或状态转移经过训练数据/历史校准后加入，避免用未经识别的固定容量制造伪精确状态。
4. **再检查更长行程与跨车辆划分。**本轮先完成了冻结trip划分的三组对照；跨车辆/时间划分属于下一轮扩展，不写成已完成。

当前建议保留三组全部结果，以hidden作为递归参考，以parallel作为速度/成本参考。下一轮优先解决“耗时低估＋显式状态如何进入能耗计算”，暂不扩大网络规模。
