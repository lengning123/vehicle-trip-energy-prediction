## 0. 当前主线：完整旅程与出发信息配对，公开资源承担机制与先验

2026-09-30六篇全文后的D09修订：不再将权重验收作为完整旅程工作的前置步骤。**换数据生成流程是主方向**：公开机制资源验收与配对旅程获取并行准备，外部预训练只是降低训练需求的工具。依据见[六篇深读](reports/literature_review_20260930/六篇全文深读与决策修订.md)与[数据路线](reports/literature_review_20260930/研究结论与数据路线.md)。

1. **新建独立的已知BEV完整旅程研究线。**稳定车辆身份/配置、真实ON/OFF、电池端时间积分、出发路线/导航快照与热状态配对。先重复路线分辨机制，再留出新车、路线和未来时间。现有PHEV任务保留，不用新BEV分数替代；若PHEV为硬要求，另需完整油电与发动机状态及独立燃油参考。
2. **公开源负责具体缺口。**EnergyVille验收停车/充电/初始热状态/附件会话；GECR帮助车辆与驾驶强度标定。不得拼接不同车不同时刻的字段为一条完整样本。原始会话/许可仍待验收，不能先称新主数据集已具备。
3. **获取公开源缺少的配对观测。**真实出发时的导航预计耗时/分段交通、初始电池与座舱温度、预调温和空调意图、完整起止电能。可从齐套校企/运营会话或可接入BEV小试点取得；当前没有联系第三方或启动采集。先验一车链路，再按堵/畅、冷/热、短/长的缺口扩充。
4. **外部车队知识减少本地训练样本需求。**IFS优先、ECT条件候选，必须共同合法字段与兼容标签，对照同结构随机初始化及简单模型。尚未加载或证明收益；原始大车队不公开。E2本地扩历史失败不能否定外部先验。
5. **第二候选为历史条件下的能量预算和区间。**某些状态不能取得时，用合法历史描述可能工况；单程和每日累计分开，独立选模/校准，检查长途与季节低估风险。不能把宽区间包装成点精度提升，不宣称已知不可约误差下限。

全文的重要边界：P15以ON/OFF和热信号改善可研究性，却用实际整程控制统计；P09先开15分钟预测下一段；P13靠已知车稳定历史，主要日累计且测试参与选剖面；P14是同一公交线路。ECT有实测均速/耗时代理，标称99%区间仅约70%覆盖。它们支持数据设计和条件分布，尚不证明当前匿名PHEV短片段可达10%。

不新增架构网格、确定逐秒速度长链或无目的扩库。当前资源顺序/范围以decision_log D09为准，D08保留第一阶段历史。

### 领域证据带来的定义修正

“trip-level”不等于“出发前”：Zhu的5.04%基于电机侧能量和实测整程工况，未含HVAC；GECR的7.12%使用实际驾驶特征并做实路偏置校准；Meta-Pec的ETTD是GPS估算轮端机械能。它们回答的任务不同，不是我们必然能达到的成绩。Sequence-aware明确借助地图API分段预估，IFS预训练则主要用路线概要、历史与起始信息，两者解决信息问题的方式不同。P14正文明确测试MAPE11.08%，不能用宣传8.69%作测试目标。P15电池电能减电机机械功的残差可能包含转换损耗；附件标签须检验独立支路边界，不能只凭命名认为已可辨识。

以下保留完整数据需求表作为采集契约；不再表示所有字段都要先从零采齐，公开资源可承担其中的机制验证。

| 已知问题 | 数据层面的解决办法 | 无法取得时的真实边界 |
|---|---|---|
| 公开轨迹首尾裁剪 | 重新记录出发至停车的完整旅程，并记录出发前停车、充电与预热状态；完整原始数据在授权环境保留，导出时再保护位置隐私 | 只能研究公开片段，不插值“恢复”未记录的冷热启动能耗 |
| 燃油估算不稳、油电混合 | 纯电主线采用有时间戳的电池端电压/电流或经验证的累计能量计量；PHEV另需独立燃油参考与供能分量 | MAF派生量继续标为估算；没有独立参考就不能宣称修成真值 |
| 出发前缺交通 | 在真实出发时保存计划路线、导航预计耗时及可得的分段交通状态，保留查询时间和来源；实际速度仅用于标签侧机制研究 | 历史实况天气/交通不自动等于当时预测；今天查交通不能补回过去的决策快照 |
| 缺热状态与附件需求 | 采集出发时电池/座舱温度、停车时长、预调温、空调开关/设定及可得功率；用部署能取得的字段建输入 | 无法取得的因素进入情景或不确定性分析；仅外温不能声称恢复全部热负载 |
| 匿名车辆与稀疏覆盖 | 保留稳定车辆标识、可核验车型和电池配置；按新车辆、长短程、城市/高速、季节、SOC等补覆盖 | 不以插值行数和重复通勤次数代替车型与环境覆盖 |
| 相同出发信息对应多个未来 | 在相同路线/车辆上重复记录不同时段与热状态，区分可观测差异与未观测波动；点估计同时评估区间和低估风险 | 不保证一个确定值覆盖所有驾驶与交通；是否可达10%需新数据验证 |

数据应组织成三张可按trip_id与时间关联的表：①出发时输入快照；②旅程中实测状态及标签；③车辆资料与历史。必须保留原始信号、单位、测量来源、时间同步和缺失标记。出发后才出现的量不回填输入表。电池端积分要核验符号、时钟、缺口，并在可行时与独立累计能量参考交叉检查；仪表SOC差不是天然精确电量真值。

先用一辆可接入车辆验证链路，再做小型多车试点与有目的的重复路线采集；数量只是工程阶段安排，不是泛化证据门槛。优先覆盖堵/畅、冷/热、短/长、空调状态差异，避免只增加相似通勤。自然驾驶可用于覆盖，受控重复需尽量保持路线、载荷等一致；不能把观察相关当因果。最终留出新的车辆和未来时间窗口，长途结论必须有对应真实旅程。

**公开数据分工的补充资源与边界。**eVED承担路线片段基准；其他纯电数据承担热状态、车辆与电池机制研究；最终仍需要一份输入与标签配套、匹配目标应用的数据作验证。不同车辆、时间和地点的路线与热状态不能拼成虚构完整样本。已核查的[TUM UDS数据](https://github.com/tumftm/electric-vehicle-uds-dataset)提供7辆纯电车、超过72,000km运行记录及电池温度等信号，但尚未确认满足计划路线/GPS需求，且许可为CC BY-NC 4.0；当前只是候选补充源，不是已验收的新主数据集。

若始终拿不到配套路线与出发信息，建议把成果定义为“给定运行工况的能量估计”或“公开路线片段的条件能耗与不确定性研究”，明确与出发前真实整程预测不同。物理仿真可补充机制先验和条件覆盖，不能把仿真标签当现实真值或用仿真测试证明部署精度。

## 1. 真正要解决的问题

在车辆尚未走完所给路线、只知道路线、起始状态和已完成历史的条件下，估计这一段路线会消耗多少电和油。用途是支持出行能量预算与路线决策；目前只验证离线估计，尚未验证导航路线选择、缺电风险或实际续航决策的收益。

这不是“已知道实际速度后重建功率”，也不是“用前60秒预测后10秒”。后两者可用于诊断，但不能替代当前任务。我们需要学习的是可用信息条件下的能耗分布；同样路线和起始SOC不保证唯一能耗。尚未量化剩余随机性，不能宣称到达不可突破的误差下限。

### 当前目标必须分开命名

| 对象 | 标签/输出 | 可以说明什么 |
|---|---|---|
| EV | 带符号电池端净电量，kWh | 记录片段内的净电池支出；不含外部充电损耗 |
| PHEV电池 | 带符号电池端净电量，kWh | 电池支出与回充的净额，受发动机供能策略影响 |
| PHEV燃油 | 估算燃油体积，L | Fuel Rate或MAF推算结果，非独立量热真值 |
| 当前PHEV总量 | 电池净电量 + 8.85 kWh/L × 燃油L | 冻结的油电折算能量口径，不是轮端机械功、费用或碳排放 |

电池功率采用 `P_batt(kW) = -I(A) × V(V) / 1000`，按实测时间积分。V4分量为放电 `D=∫max(P_batt,0)dt`、回充 `R=∫max(-P_batt,0)dt`，满足 `E_batt=D-R`。PHEV回充可能来自发动机，不能统称再生制动。总量保留带符号值；更换目标不构成模型性能提升。

8.85是本项目冻结折算系数，不代表每辆车实测燃料热值。电池端与燃料端边界不同，跨EV/PHEV比较效率时必须说明；PHEV总量不能单独回答“还剩多少电”。后续应同时提供电池、燃油和总量，是否转为概率区间或按工况拆任务由诊断证据决定，不擅自替换目标。

### “整程”和“出发前”的现实边界

缓存manifest明确是 `full-recorded-trip`。VED原论文说明公开轨迹经过首尾隐私裁剪、地理围栏和主要路口边界处理；eVED是在VED记录上做地图增强。**因此当前整程指公开记录片段的完整时间轴，不保证涵盖真实点火至熄火旅程。**这一边界得到来源和本地manifest支持；每条记录裁掉多少、是否已经热车，当前未知。[VED原论文，III节](https://arxiv.org/html/1905.02081)、[eVED原论文](https://arxiv.org/html/2203.08630)

由此提出而尚未证实的解释：片段首点SOC/外温可能不足以描述发动机、电池和座舱热状态；记录起点不等于冷启动。路线本身又由实际走过的GPS匹配得到，是“计划路线已知”的离线代理。尚未验证路线偏离，也未证明全部地图属性可按历史时点在出发前重建。

## 3. 目前模型为什么可能做不好

1. **运行情境不完整。** 限速和路口数量不能确定排队秒数、红灯相位、驾驶操作和热负载。耗时影响附件能量，但仅知道耗时仍不知道负载功率。
2. **需求与供能不是同一件事。** 路线动力学描述车轮需要多少功；PHEV由电池还是发动机供给、是否同时充电、效率和热机过程还要另解释。总量折算也没有消除这些差异。
3. **目标本身有估算误差。** 原始采样间隔、燃油修正缺失、RPM/MAF不同步等可能让模型在拟合不稳定标签。
4. **优化的量与决策的量不一致。** 路段MAE低不保证整程求和准确；MAPE又放大小能量行程的重要性。高估和低估可能相互抵消，不能用总误差小证明分量正确。
5. **覆盖不足。** 27辆车、3辆EV和大量短路线，不能用二十万路段代替多车辆、多工况证据。

我的判断：**任务定义/标签与信息缺失优先；机制和覆盖其次；特征表达与目标对齐需要受控验证；没有足够证据把主要瓶颈放在网络规模或普遍训练不足。**这是研究优先级，不是已完成的因果分解，五项可证伪假设见[hypotheses.md](hypotheses.md)。

## 4. 领域机制与理论预期

简化车轮需求为 `F ≈ m·a + m·g·Crr + 0.5·ρ·CdA·v_rel² + m·g·sin(坡度)`。电驱供能还需区分正牵引效率、制动回收限制和附件功率。车辆参数与速度时间轨迹共同决定能量流，这是FASTSim官方模型的基本组织方式。[FASTSim官方说明](https://natlabrockies.github.io/fastsim/getting-started/)

以下为据力学作出的条件推导，不是本项目已估计的因果系数：

| 理论预期 | 对建模的约束/可检验诊断 |
|---|---|
| 固定路线与其他条件，提高高速行驶速度会增加单位距离风阻能量（无风近似随v²） | 整程均速不能代替距离加权v²；不能对总电耗施加无条件速度单调性，慢行会增加附件工作时间 |
| 附件能量约为平均附件功率×耗时 | 优先检验耗时×HVAC/温度/热状态交互；停车距离近零不代表耗能近零 |
| 同净高差的上下坡与平路能耗未必相同 | 驱动/回收效率不对称，保留正负能流；不能用平均坡度覆盖全部机制 |
| 更重车辆在其他条件相同时增加滚阻和加速需求 | 载荷缺失可能形成条件残差；历史等效系数不等于辨识出真实质量 |
| PHEV发动机介入受电池状态、动力需求和热负载影响 | 不能预设初始SOC与总量全局单调；应检查SOC×温度×运行需求交互 |

PHEV发动机可参与驱动和电池充电；电池不足、加速和较强热负载都可能触发介入，支持把需求与供能分开考虑。[美国能源部AFDC](https://afdc.energy.gov/vehicles/electric-basics-phev)

限速、设施密度、外温、历史均值主要是代理变量：分别代理可能的运行速度、起停机会、热负载和既往车辆/驾驶情境，不能将特征重要性解释为真实因果。电池高SOC/温度对回充限制的具体阈值、冷机效率和空调控制规律需要车型技术资料，当前没有可用的逐车型可靠参数；不猜数值或用统一Leaf参数冒充真实PHEV机制。

燃油估算沿用Fuel Rate优先、MAF回退；原论文给出E10空燃比14.08及STFT/LTFT修正，动态空燃比不可得。745g/L、缺失修正归零和MAF分支RPM门控是本项目显式工程假设，不能统称论文真值。[VED原论文，Algorithm 1](https://arxiv.org/html/1905.02081)

## 5. 当前成绩与成功标准

MAPE<10%是既定研究愿望，尚无可达性证据。当前只对真值>0.1kWh计算：验证287/288、开发基准528/539；其他样本保留MAE/RMSE/偏差。每次同时报MAE、RMSE、WAPE、偏差、MAPE覆盖、车型和车辆宏平均，不能抬高阈值制造改善。

阶段筛选只按冻结验证门槛；最终确认需相同信息、目标、划分及可比预算的强基线、多种子和车辆簇配对不确定性。外部检验决定能否外推；业务上可接受的绝对误差、低估风险与计算成本尚未量化，不能把论文单一指标当作业务验收。

## 6. 持续维护规则

每轮由Research Manager主动提出判别性最强的下一步。结束时先给≤300字摘要，再写做了什么、学到了什么、因此做什么；更新五个假设的支持/反证/缺证和置信变化。实验记录追加可追溯事实，当前理解和假设则修订到最新状态；已否定的旧结论保留历史并标明失效原因。启动新实验前完成七层检查，不能把上一轮的“下一步”机械执行成无限队列。
